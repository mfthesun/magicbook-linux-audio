# Микрофон проводной гарнитуры на HONOR MagicBook Pro 16 2024 (DRA-XX, ALC256)

Комбинированный разъём 3.5 мм (наушники + микрофон) на этом ноутбуке в стоковом Linux записывает цифровую тишину.
Здесь описаны причина, исправление и способ проверки.

## Причина

- BIOS оставляет пин 0x19 (микрофон гарнитуры) в конфигурации `0x411111f0` («N/A»), поэтому парсер кодека не строит для него путь захвата.
- BIOS оставляет переключатель комбо-джека (coef `0x45`) в состоянии TRS (`0xc089`): контакт микрофона отрезан от кодека.
  Нормальные значения после определения типа гарнитуры: `0xd489` (CTIA), `0xe489` (OMTP).

Гипотеза про coef `0x1b`, с которой начиналась работа, не подтвердилась: на голос он не влияет.

## Исправление

Патч для ядра: `../speakers-fix/patch/0002-ALSA-hda-realtek-Enable-headset-mic-on-HONOR-MagicBo.patch`.

- пин 0x19 настраивается как микрофон гарнитуры (`0x03a1113c`, «headset mic without its own jack detect»), то же значение уже используется для HONOR MRB-XXX и в квирках VAIO;
- цепочка fixup продолжается общим обработчиком `alc_fixup_headset_mode`, который определяет тип гарнитуры (CTIA/OMTP) на каждое событие джека и выставляет coef `0x45`.

Статус: **принят** 04.10.2026 в ветку `for-next` дерева sound (коммит `af53cdc10`). Треды: [v1](https://lore.kernel.org/linux-sound/20261002221850.12443-1-mfthesun@vivaldi.net/), по замечанию мейнтейнера добавлен тег `Fixes:` → [v2](https://lore.kernel.org/linux-sound/20261003133325.97507-1-mfthesun@vivaldi.net/).

Пока патча нет в вашем ядре, тот же код доступен через DKMS (`../speakers-fix`, параметр модуля `honor_dra_mic`, режимы 0–4,
по умолчанию 4, что соответствует патчу). Таблица режимов и переключатель `set-mic-mode.sh` описаны в `../speakers-fix/README.md`.

## Проверка

Скрипты в этой папке (нужен Python 3, PipeWire, root; `headset-factorial.py` и `headset-mic-check.py` используют соседний `hda-verb.py`):

- `headset-factorial.py` - факторный тест 2×2 (какое из двух условий возвращает голос), по явному источнику PipeWire (`--target`), метрика SNR = p90 речи минус p90 тишины, порог голоса 12 дБ;
- `headset-mic-check.py` - только чтение: режим модуля, строки dmesg, регистры, интерпретация `coef 0x45`, запись и SNR. Ключ `--hotplug` просит вынуть и вставить гарнитуру.

Логи пишутся в `runs/` рядом со скриптом (в репозиторий не входят).

## Результаты (Ubuntu 7.0.0-34, DKMS с тем же кодом, Apple EarPods, CTIA)

- холодный старт и горячая вставка: голос есть, SNR около 29-33 дБ, `coef 0x45 = 0xd489`, режим сохраняется во время записи;
- без исправления аналоговый захват - цифровая тишина;
- без привязки к DAC из патча 0001 (`honor_dra_share_dac=0`, как после исправления 0003): SNR 29.7 дБ, CTIA (05.10.2026);
- OMTP-гарнитуры не проверялись (нет оборудования); микрофон после сна не проверялся.

## Известные ограничения и открытые вопросы

- Чувствительность и клиппинг при Mic Boost 30 дБ - вопрос пользовательского уровня (усиление, PipeWire), ядром не решается.
- Автоматическое переключение между цифровым микрофоном и микрофоном гарнитуры (WirePlumber/UCM) пока не сделано.
- `dynamic_debug` недоступен (Operation not permitted, вероятно lockdown при Secure Boot), поэтому вердикт автоопределения судим по регистрам.
- Щелчки при вставке и выдёргивании штекера есть и с headset mode, и без него (сравнение `honor_dra_mic` 0 и 4, 04.10.2026): их даёт не этот патч.
- Вопрос о привязке к DAC из патча 0001 закрыт: она ничего не меняет и убрана отдельным патчем (коммит `5cc1749b5`), см. `../speakers-fix/README.md`.
